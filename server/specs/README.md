# server — specs

What we are **building**: one file per feature or milestone, `<feature>.md`
(for example `m1-run-cost-badge.md`). Suggested sections:

- **Goal**: the user-visible outcome
- **Scope**: what is in, what is explicitly out
- **Design**: contracts, routes, tables, UI touched
- **Acceptance**: how we know it works (tests, e2e flow)
- **Status**: draft / in progress / done (link the PR)

Once a feature ships, move the lasting "how it works" knowledge to `docs/`.
